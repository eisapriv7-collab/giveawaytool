HOW TO UPLOAD THIS TO GITHUB (site is on Vercel)
=================================================

WHAT'S INSIDE
  index.html                  <- your mini-games page (CHETOPOLY button already wired in)
  chetopoly/                  <- the game folder. DO NOT rename, DO NOT flatten.
    index.html                <- launcher (pick Version 1 or 2)
    v1.html
    v2.html
    src/engine.js
    vendor/three.module.js

NOT inside (on purpose, per your request — they already exist in your repo):
  api/            (keep it where it is: api/chatroom.js)
  chatroom.js

WHY YOUR 404 HAPPENED
  Two index.html files are fine as long as they live in DIFFERENT folders.
  The 404 means the chetopoly FOLDER was missing or its files were dropped in the
  wrong place, so ./chetopoly/index.html didn't exist. Drag the folder AS A FOLDER.

STEP 1 — GitHub web UI (no terminal needed)
  1. github.com -> your repo -> Add file -> Upload files
  2. Drag the "chetopoly" FOLDER (the whole folder, not its contents) onto the
     upload box. GitHub keeps the folder structure.
  3. Also drag "index.html" onto the box. It will warn that the file already
     exists -> that's correct, it replaces the old one.
  4. Commit directly to the main branch (usually "main").
  5. Repeat step 1-4 for any future changes the same way.

  After committing, your repo tree must look like this:
     your-repo/
       index.html
       api/chatroom.js        (already there, untouched)
       chetopoly/
         index.html
         v1.html
         v2.html
         src/engine.js
         vendor/three.module.js

STEP 2 — Vercel
  - If your GitHub repo is connected as a Vercel project, Vercel redeploys
    automatically on every push. Watch the deploy finish in the Vercel dashboard.
  - Framework preset must be "Other" (plain static site, no build step).
  - Output directory: leave empty (root).
  - No vercel.json needed. Static files + your existing api/chatroom.js work as-is.

STEP 3 — test
  - https://YOUR-VERCEL-DOMAIN/                 -> mini-games page
  - click CHETOPOLY                              -> launcher
  - click PLAY VERSION 1 or 2                    -> 3D board
  - If the button ever can't find the game it shows a clear alert instead of a 404 page,
    and it automatically falls back to v1.html if a host refuses folder-index pages.

EXTRA
  - Deep links:  /chetopoly/?v=1  and  /chetopoly/?v=2  skip the launcher.
  - The launcher's "Back to Mini Games" link returns to the dashboard.
  - If you later want the button to open a version directly, change the first entry
    of the cands list in index.html (search for "openChetopoly").

PREVIEW PANES / EMBEDDED IFRAMES (Arena viewer, sandboxed embeds)
-----------------------------------------------------------------
Such viewers block localStorage, alert() and window.open by design. That is why
"Create Giveaway" appeared dead there: the storage write threw, and the error
alert was silently swallowed. index.html now ships an embed-safety shim:
  * in-memory localStorage substitute (only when the native one is unusable)
  * on-screen toasts instead of alert(), so messages are always visible
  * when a pop-up is refused, the game opens in-page in a full-screen overlay
    with a red "Close game" bar; entrants travel via an &st= URL parameter
On your Vercel site (a normal top-level tab) nothing changes: real pop-ups,
real localStorage, native alerts replaced by the same styled toasts.
